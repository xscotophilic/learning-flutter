# Secure Storage & Session Persistence

Persist user sessions locally so users remain logged in across app restarts. Use encrypted storage instead of plain-text alternatives like `shared_preferences` to protect authentication tokens.

## Add the Dependency

Add `flutter_secure_storage` to `pubspec.yaml`:

```yaml
dependencies:
  flutter_secure_storage: ^11.0.0
```

## 1. Storage Abstraction

Define a `LocalStorage` interface to isolate data sources from third-party storage packages:

```dart
abstract interface class LocalStorage {
  Future<void> write(String key, String value);
  Future<String?> read(String key);
  Future<void> delete(String key);
  Future<void> clear();
}
```

### Why we use this interface

- **Decouple code**: The data layer does not need to know whether the app stores data in Keychain, Keystore, or a local database.
- **Simplify testing**: Mock storage in unit tests easily without dealing with platform-specific secure channels.

## 2. Secure Storage Implementation

Implement the interface using `FlutterSecureStorage`:

```dart
final class SecureLocalStorage implements LocalStorage {
  const SecureLocalStorage(this._storage);

  final FlutterSecureStorage _storage;

  @override
  Future<void> write(String key, String value) => _storage.write(key: key, value: value);

  @override
  Future<String?> read(String key) => _storage.read(key: key);

  @override
  Future<void> delete(String key) => _storage.delete(key: key);

  @override
  Future<void> clear() => _storage.deleteAll();
}
```

The package uses Keychain Services on iOS and Keystore on Android to encrypt values.

## 3. Session Persistence Flow

Use `AuthLocalDataSource` to store and load the token and user profile JSON:

```dart
class AuthLocalDataSource {
  const AuthLocalDataSource(this._storage);
  final LocalStorage _storage;

  Future<void> saveSession(String token, UserModel user) async {
    await Future.wait([
      _storage.write('session_token', token),
      _storage.write('session_user', jsonEncode(user.toJson())),
    ]);
  }

  Future<(String, UserModel)?> loadSession() async {
    final token = await _storage.read('session_token');
    final userJson = await _storage.read('session_user');

    if (token == null || userJson == null) return null;

    try {
      final decoded = jsonDecode(userJson) as Map<String, dynamic>;
      return (token, UserModel.fromJson(decoded));
    } catch (_) {
      await clearSession();
      return null;
    }
  }

  Future<void> clearSession() async {
    await Future.wait([
      _storage.delete('session_token'),
      _storage.delete('session_user'),
    ]);
  }
}
```

### Key Decisions

#### Run writes in parallel

Writing and deleting keys to disk is slow. Run them in parallel using `Future.wait` to avoid waiting for one to complete before starting the next.

#### Serialize to a single JSON string

Save the entire `UserModel` as one JSON string instead of using separate keys for name, email, and ID. This ensures user profiles are updated atomically and avoids multiple slow, encrypted disk reads.

#### Avoid crashes from schema changes

If the user model structure changes, reading old cached JSON throws an exception. Wrap the parsing logic in a `try-catch` block. On failure, clear the storage and return `null` so the user is prompted to sign in again instead of crashing on launch.
