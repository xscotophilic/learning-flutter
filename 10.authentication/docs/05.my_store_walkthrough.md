# The `my_store` Showcase App

## 1. App Startup Flow (`SplashNotifier`)

The splash screen waits for both session restore and app status checks before navigating forward, when we restore session we populate user and token, and that token we use it for all network requests made after that. We use `ref.read` for auth to avoid subscribing to future state changes, and once the session is restored, the splash screen doesn't need to rebuild when auth changes later:

```dart
@riverpod
class SplashNotifier extends _$SplashNotifier {
  @override
  Future<SplashState> build() async {
    final results = await (
      ref.read(authProvider.future), // Retrieve saved session first
      ref.watch(checkAppStatusUseCaseProvider).execute(),
    ).wait;

    final (_, state) = results;
    return state;
  }
}
```

> [!IMPORTANT]
> The calls inside `.wait` are only safe to run in parallel because none of them currently depend on the auth token.
> If a future call _does_ need the token, it must first wait for session restoration by doing `await ref.read(authProvider.future)` - this awaits `authProvider`'s `build()` completing, including its session restore/initialization, before proceeding. After that, calls that depend on the restored session can be grouped together and run in parallel. Skipping this and reading the token directly could return a stale or null value if `authProvider` hasn't finished initializing yet.

## 2. Profile UI & Route Guards (`AppDrawer`)

The navigation drawer changes based on the user's status:

- **Display Profile**: Shows the user's name, photo, and logout button when authenticated, or a Sign In button when not.
- **Loading Status**: Shows a shimmer effect when `isMutating` is true.
- **Guarded Screens**: Blocks entry to "Orders" and "My Products" if guest, popping the drawer and showing a SnackBar warning.

For guarded screens, we check `authTokenProvider` directly instead of `authProvider`. The token is a plain `String?` so reading it is instant and doesn't re-trigger any async work:

```dart
_buildListTile(
  context: context,
  title: 'Orders',
  icon: Icons.receipt_long_outlined,
  tapHandler: () {
    final token = ref.read(authTokenProvider);
    if (token == null) {
      Navigator.of(context).pop();
      AppSnackBar.showErrorSnackBar(
        context,
        message: 'Please sign in to view your orders.',
      );
      return;
    }
    Navigator.of(context).pushReplacementNamed(OrdersPage.routeName);
  },
);
```

## 3. Action Guards (Favorites & Cart)

Favorites and cart mutations hit the API, so we block them for guests. We check the token at the point of interaction, not inside the notifier, so the UI can show a relevant message before anything is dispatched.

### Favorite Button

```dart
onTap: () {
  final token = ref.read(authTokenProvider);
  if (token == null) {
    AppSnackBar.showErrorSnackBar(
      context,
      clearSnackBars: true,
      message: 'Please sign in to add items to your favorites.',
    );
    return;
  }
  _controller.forward(from: 0.0);
  ref.read(favoritesProvider.notifier).toggle(widget.productId);
}
```

The animation (`_controller.forward`) only runs after the guard passes, so guests never see the heart wiggle animation either.

## 4. Wiping Data on Logout

When the user signs out, the cart and favorites should reset immediately, not show the previous user's data while the new state loads. Both `CartNotifier` and `FavoritesNotifier` watch `authTokenProvider`. When the token becomes `null`, Riverpod rebuilds the provider and the `build()` method returns empty data before any API call is made:

```dart
@override
Future<CartSnapshot<HydratedCartItem>> build() async {
  final token = ref.watch(authTokenProvider);
  if (token == null) {
    return CartSnapshot(isMutating: false, cart: Cart.empty());
  }
  // fetch from API only when authenticated
  // ...
}
```

The cart empties the same frame the token clears, no flash of stale data.

## 5. Session Expiration Notification

When the server returns a `401 Unauthorized`, the interceptor handles it globally so individual screens don't need to:

1. `AuthInterceptor` intercepts the 401 response and clears the in-memory token.
2. It emits a `SessionExpiredEvent` on the event bus.
3. The root `App` widget listens and shows a global SnackBar, then consumes the event so it doesn't fire again:

```dart
@override
Widget build(BuildContext context, WidgetRef ref) {
  ref.listen(eventBusProvider, (_, event) {
    if (event == null) return;

    switch (event) {
      case SessionExpiredEvent():
        _showSessionExpiredSnackBar();
    }

    ref.read(eventBusProvider.notifier).consume();
  });
  // ...
}
```

Calling `consume()` resets the event bus to `null` so the listener doesn't re-trigger on subsequent builds.
