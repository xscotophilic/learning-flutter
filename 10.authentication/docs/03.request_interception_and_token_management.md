# Request Interception & Token Management

Attach authentication tokens to outgoing network requests automatically, and handle expired sessions globally when the backend returns a `401 Unauthorized` status.

## 1. Interceptor Interface

Define the `HttpInterceptor` interface to hook into requests and responses:

```dart
abstract interface class HttpInterceptor {
  Future<void> onRequest(http.BaseRequest request);
  Future<void> onResponse(http.BaseRequest request, http.StreamedResponse response);
}
```

### Why we use this interface

- **Keep client code clean**: Prevent the basic `ApiClient` from containing custom authorization header logic.
- **Run multiple tasks**: Chain different interceptors together to handle tasks like logging, error handling, or headers.

## 2. Request & Response pipeline

Implement `ChainedClient` extending `http.BaseClient` to run a list of interceptors before and after requests:

```dart
class ChainedClient extends http.BaseClient {
  ChainedClient(this._inner, {this.interceptors = const []});

  final http.Client _inner;
  final List<HttpInterceptor> interceptors;

  @override
  Future<http.StreamedResponse> send(http.BaseRequest request) async {
    for (final i in interceptors) {
      await i.onRequest(request);
    }
    final response = await _inner.send(request);
    for (final i in interceptors) {
      await i.onResponse(request, response);
    }
    return response;
  }
}
```

Because it extends `http.BaseClient`, you can pass `ChainedClient` anywhere a standard client is expected. When a request runs, the client:

1. Loops through the interceptors to update request headers.
2. Sends the request to the network.
3. Passes the response back through the interceptors to check status codes.

## 3. Appending Tokens & Intercepting 401s

Implement `AuthInterceptor` to inject authorization headers and intercept session expiration:

```dart
class AuthInterceptor implements HttpInterceptor {
  AuthInterceptor({required this.tokenProvider, this.onUnauthorized});

  final String? Function() tokenProvider;
  final void Function()? onUnauthorized;

  @override
  Future<void> onRequest(http.BaseRequest request) async {
    final token = tokenProvider();
    if (token != null) {
      request.headers['Authorization'] = 'Bearer $token';
    }
  }

  @override
  Future<void> onResponse(http.BaseRequest request, http.StreamedResponse response) async {
    if (response.statusCode == 401) {
      onUnauthorized?.call();
    }
  }
}
```

### Why pass a function for the token

Because the active token changes when users sign in or sign out, passing a function ensures the interceptor reads the latest token value on every request.

### Handling 401 Unauthorized

If the server returns a `401` status code, the session is expired. The interceptor catches this response and runs the `onUnauthorized` callback.

## 4. Riverpod State Integration

Manage the token in memory and configure the HTTP client with the interceptor.

### AuthToken Provider

Keep the active token state in memory:

```dart
@Riverpod(keepAlive: true)
class AuthToken extends _$AuthToken {
  @override
  String? build() => null;

  void setToken(String? token) {
    state = token;
  }
}
```

Separate the token state from the user profile model. This allows other providers to watch the token without reloading when user details (like profile pictures) update.

### Hooking Up Interceptors

Inject the interceptor pipeline and build `ChainedClient` inside the `apiClientProvider`:

```dart
@Riverpod(keepAlive: true)
AuthInterceptor authInterceptor(Ref ref) {
  return AuthInterceptor(
    tokenProvider: () => ref.read(authTokenProvider),
    onUnauthorized: () {
      ref.read(authTokenProvider.notifier).setToken(null);
      ref.read(eventBusProvider.notifier).emit(SessionExpiredEvent());
    },
  );
}

@Riverpod(keepAlive: true)
ApiClient apiClient(Ref ref) {
  final httpClient = ChainedClient(
    ref.watch(httpClientProvider),
    interceptors: [ref.watch(authInterceptorProvider)],
  );

  return ApiClient(
    httpClient: httpClient,
    baseUrl: 'https://your-app.domain/api/v2',
  );
}
```

When a `401` error occurs, clear the token and emit a `SessionExpiredEvent`. The main `App` widget listens for this event to display a logout message.
