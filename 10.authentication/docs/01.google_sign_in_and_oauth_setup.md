# Google Sign-In & OAuth Setup

Configure Google Sign-In and OAuth credentials so native apps can sign in and generate ID tokens for the backend to verify.

## Adding the Dependency

Include the `google_sign_in` package in `pubspec.yaml`:

```yaml
dependencies:
  google_sign_in: ^x.y.z
```

## 1. Google Cloud Console Configuration

Create a project in the [Google Cloud Console](https://console.cloud.google.com/) to authorize the app.

### Configure the OAuth Consent Screen

1. Go to **APIs & Services** > **OAuth consent screen**.
2. Select **External** and complete the required app configuration fields.

### Create Credentials (OAuth Client IDs)

Create one Client ID per platform (three total) under **APIs & Services** > **Credentials** > **Create Credentials** > **OAuth client ID**:

1. **Web application**: Required even if you do not have a website. The backend uses the Web client ID as the `GOOGLE_CLIENT_ID` to verify tokens: it's what Google puts in the token's `aud` field when you request the ID token with `serverClientId`. Android and iOS client IDs aren't used for this; they just authorize the native sign-in UI (via package name/SHA-1 or bundle ID).
2. **Android**: Requires your app's package name and SHA-1 signing fingerprint. You can check how to get the SHA-1 fingerprint [here](#retrieving-the-sha-1-fingerprint).
3. **iOS**: Requires your app's Bundle ID.

> [!NOTE]
> Do not confuse Google OAuth client IDs with Firebase's `google-services.json` or `GoogleService-Info.plist` configuration files. If you are using Google Sign-In without Firebase, the `google_sign_in` plugin does not require these Firebase files. Note down the OAuth client IDs from Google Cloud Console and configure the required IDs manually.

## 2. Android Configuration & Keystores

Android apps require a SHA-1 fingerprint to verify their identity with Google services.

### Retrieving the SHA-1 Fingerprint

Use the debug keystore for development. Generate a custom keystore for release builds.

#### Debug Keystore (Development)

Run this command to get the development SHA-1 fingerprint:

```bash
keytool -list -v \
  -alias androiddebugkey \
  -keystore ~/.android/debug.keystore \
  -storepass android \
  -keypass android
```

#### Release Keystore (Production)

1. Generate the keystore file:
   ```bash
   keytool -genkeypair -v \
     -keystore ~/upload-keystore.jks \
     -keyalg RSA \
     -keysize 2048 \
     -validity 10000 \
     -alias upload
   ```
2. Move `upload-keystore.jks` into the `android/` directory of your project.
3. Retrieve its SHA-1 fingerprint:
   ```bash
   keytool -list -v -keystore android/upload-keystore.jks
   ```
4. Configure Gradle for release signing. Create `android/key.properties`:

   ```properties
   storePassword=YOUR_KEYSTORE_PASSWORD
   keyPassword=YOUR_KEY_PASSWORD
   keyAlias=upload
   storeFile=/absolute/path/to/upload-keystore.jks
   ```

   Then update `android/app/build.gradle.kts` to load it:

   ```kotlin
   import java.util.Properties

   plugins {
       id("com.android.application")
       id("kotlin-android")
       id("dev.flutter.flutter-gradle-plugin")
   }

   val keystoreProperties = Properties()
   val keystorePropertiesFile = rootProject.file("key.properties")

   if (keystorePropertiesFile.exists()) {
       keystoreProperties.load(keystorePropertiesFile.inputStream())
   }

   android {
       // ...

       signingConfigs {
           if (keystorePropertiesFile.exists()) {
               create("release") {
                   keyAlias = keystoreProperties["keyAlias"] as String
                   keyPassword = keystoreProperties["keyPassword"] as String
                   storeFile = file(keystoreProperties["storeFile"] as String)
                   storePassword = keystoreProperties["storePassword"] as String
               }
           }
       }

       buildTypes {
           debug {
               signingConfig = signingConfigs.getByName("debug")
           }
           release {
               signingConfig = if (keystorePropertiesFile.exists()) {
                   signingConfigs.getByName("release")
               } else {
                   signingConfigs.getByName("debug")
               }
           }
       }
   }
   ```

> [!IMPORTANT]
> Add the SHA-1 fingerprint to the **Debug** and **Release** OAuth consent screen configurations in Google Cloud Console. Otherwise, Google Sign-In will fail on Android devices.

> [!IMPORTANT]
> Never commit the keystore files (`upload-keystore.jks`) and `key.properties` file to version control. Add them to `.gitignore` if not already there.

## 3. iOS Configuration

Add the iOS Client ID and its Reversed Client ID URL scheme to `ios/Runner/Info.plist`.

- **Android**: Does not pass client IDs in code or config; Google resolves them via package name and SHA-1.
- **iOS**: Explicitly requires `GIDClientID` and `CFBundleURLTypes` reversed client ID scheme to return to the app after sign-in.

Update `ios/Runner/Info.plist`:

```xml
    <key>GIDClientID</key>
    <string>YOUR_IOS_CLIENT_ID.apps.googleusercontent.com</string>

    <key>CFBundleURLTypes</key>
    <array>
      <dict>
        <key>CFBundleTypeRole</key>
        <string>Editor</string>
        <key>CFBundleURLSchemes</key>
        <array>
          <!-- REVERSED_CLIENT_ID for the iOS client -->
          <string>com.googleusercontent.apps.YOUR_IOS_CLIENT_ID</string>
        </array>
      </dict>
    </array>
```

## 4. Dart Integration

Initialize `GoogleSignIn` passing the **Web** client ID to `serverClientId`. This forces Google to issue an ID token audienced to the Web client ID so the backend can verify it.

```dart
final googleSignIn = GoogleSignIn(
  serverClientId: 'YOUR_WEB_CLIENT_ID.apps.googleusercontent.com',
);
```
