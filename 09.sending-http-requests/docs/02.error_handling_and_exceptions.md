# Error Handling & Network Exceptions

Network requests can fail for many reasons: offline devices (`SocketException`), slow servers (`TimeoutException`), bad payloads (`FormatException`), or HTTP error status codes (`4xx`/`5xx`).

Instead of passing raw, low-level Dart/IO exceptions to your UI, map them to a sealed domain-level hierarchy: `ApiException`.

## The `ApiException` Hierarchy

Use a `sealed class` to represent all API error conditions. This allows the compiler to enforce exhaustive pattern matching when you handle errors in the UI.

### `api_exception.dart` Implementation

```dart
sealed class ApiException implements Exception {
  const ApiException({this.statusCode, required this.message});

  final int? statusCode;
  final String message;
}

class NoInternetException extends ApiException {
  const NoInternetException({super.message = 'No internet connection'});
}

class RequestTimeoutException extends ApiException {
  const RequestTimeoutException({super.message = 'Request timed out'});
}

class ParsingException extends ApiException {
  const ParsingException({super.message = 'Failed to parse data'});
}

class BadRequestException extends ApiException {
  const BadRequestException({super.message = 'Bad Request'});
}

class UnauthorizedException extends ApiException {
  const UnauthorizedException({super.message = 'Unauthorized'});
}

class ForbiddenAccessException extends ApiException {
  const ForbiddenAccessException({
    super.statusCode = 403,
    super.message = 'Forbidden access',
  });
}

class NotFoundException extends ApiException {
  const NotFoundException({
    super.statusCode = 404,
    super.message = 'Resource not found',
  });
}

class ServerException extends ApiException {
  const ServerException({
    super.statusCode,
    super.message = 'Server error',
    this.error,
  });

  final Object? error;
}
```

## Mapping HTTP Status Codes & Exceptions

When HTTP response is received, if response status code is 4xx or 5xx or any other error, then intercept them inside `ApiClient`, then map them to `ApiException` subclasses, extract message from response body if exists, using `_extractMessage()` helper method:

```dart
String? _extractMessage(dynamic decodedBody) {
  if (decodedBody is! Map<String, dynamic>) return null;

  final message = decodedBody['message'];
  return message is String ? message : null;
}

ApiException _mapErrorResponse(int statusCode, dynamic decodedBody) {
  final message = _extractMessage(decodedBody);
  switch (statusCode) {
    case 400:
      return BadRequestException(message: message ?? 'Bad Request');
    case 401:
      return UnauthorizedException(message: message ?? 'Unauthorized');
    case 403:
      return ForbiddenAccessException(message: message ?? 'Forbidden');
    case 404:
      return NotFoundException(message: message ?? 'Not Found');
    default:
      return ServerException(
        statusCode: statusCode,
        message: message ?? 'Server error',
      );
  }
}
```

### Exception Mapping Summary Table

| Failure Cause            | Native Exception / Status Code          | Mapped `ApiException` Class |
| :----------------------- | :-------------------------------------- | :-------------------------- |
| Device Offline / No DNS  | `SocketException`                       | `NoInternetException`       |
| Request Exceeded Timeout | `TimeoutException`                      | `RequestTimeoutException`   |
| Invalid JSON Format      | `FormatException`                       | `ParsingException`          |
| HTTP 400                 | `400` Status Code                       | `BadRequestException`       |
| HTTP 401                 | `401` Status Code                       | `UnauthorizedException`     |
| HTTP 403                 | `403` Status Code                       | `ForbiddenAccessException`  |
| HTTP 404                 | `404` Status Code                       | `NotFoundException`         |
| HTTP 500+ / Other        | remaining `4xx` / `5xx` / Unknown Error | `ServerException`           |

## Handling Exceptions in UI & Presentation Layer

Riverpod wraps any thrown error in an `AsyncError` object. In your UI, listen to the provider and use pattern matching on `ApiException` subclasses to show user-friendly error messages:

```dart
ref.listen<AsyncValue<void>>(myProductsNotifierProvider, (previous, next) {
  if (next is AsyncError) {
    final error = next.error;
    final message = switch (error) {
      NoInternetException(:final message) => message,
      NotFoundException(:final message) => message,
      UnauthorizedException(:final message) => message,
      ApiException(:final message) => message,
      _ => 'An unexpected error occurred.',
    };

    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(content: Text(message)),
    );
  }
});
```
