# API Repositories & Riverpod DI Integration

Swap mock memory repositories with concrete REST API implementations. Because the rest of the application depends on abstract repository interfaces, you only need to update the providers.

## API Repository Pattern

Every API-backed repository follows a consistent pattern to communicate with the network.
Data flows sequentially:

1. **Request Out**:
   ```text
   [Domain Entity] ────(fromDomain)────> [Model Class] ──(──toJson)────> [HTTP JSON Request Body]
   ```
2. **Response In**:
   ```text
   [HTTP JSON Response] ────(fromJson)────> [Model Class] ──(──toDomain)────> [Domain Entity]
   ```

The CRUD operations are implemented in `api_product_repository.dart` if you want to take a look.

### Fetching Data

Data flows from the network to the domain layer:

```dart
@override
Future<Cart<CartItem>> getOrCreateCart() async {
  final json = await apiClient.get('/cart');
  return CartPayloadModel.fromJson(json as Map<String, dynamic>).toDomain();
}
```

### Sending Data

Data flows from the domain to the network layer.

```dart
@override
Future<Product> createProduct(Product product) async {
  final payload = ProductModel.fromDomain(product).toJson();
  final json = await apiClient.post('/products', body: payload);
  return ProductModel.fromJson(json as Map<String, dynamic>).toDomain();
}
```

## Repository Caching Strategy

To optimize network traffic, `ApiProductRepository` maintains an in-memory cache map (`_allProductsCache`). When fetching products by a list of IDs, we only request IDs that are missing from the cache:

```dart
final missingIds = productIds.where((id) => !_allProductsCache.containsKey(id)).toList();

if (missingIds.isNotEmpty) {
  final json = await apiClient.post('/products/bulk', body: {'ids': missingIds});
  _cacheProductsFromResponse(json as Map<String, dynamic>);
}

return productIds.map((id) => _allProductsCache[id]).whereType<Product>().toList();
```

## Swapping Repositories in Dependency Injection

Override repository providers in `repository_providers.dart` to swap the mock implementations with API-backed repositories. The UI and use cases require no changes since they reference the abstract interfaces:

```dart
@Riverpod(keepAlive: true)
ProductRepository productRepository(Ref ref) {
  return ApiProductRepository(ref.watch(apiClientProvider));
}
// Repeat for CartRepository, FavoritesRepository, and OrdersRepository...
```

Watching `apiClientProvider` ensures that if the server configuration or network client changes, Riverpod automatically updates all repository instances without affecting the presentation or domain layers.
